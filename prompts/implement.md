## 阶段 1 — scout（侦察，只读）

读相关代码与文档，产出事实清单，写入 `reports/scout.md`：

- 每条结论带 `文件路径:行号` 证据；未验证的标注「待验证」
- 关键数据流/调用链、已有防护、已知的坑
- 列出待验证问题

## 阶段 2 — planner（规划，只读）

基于侦察结果产出实施计划，写入 `reports/plan.md`：

- 目标与 non-goals
- 冻结接口（完整签名/类型，代码块）
- 步骤拆分：每步写明改哪些文件、依赖谁、如何验收；标注可并行项
- 风险与回滚点、可机器检查的验收标准

## 阶段 3 — worker（实现）

按计划逐文件实现：

- 只碰计划授权的文件；发现计划有错就停下报告，不要自行"顺手修正"
- 每轮改动结束前跑 `npm run typecheck && npm test`（或项目等价命令），失败修复或回滚（同一问题最多重试 2 次）
- 验证输出原样写进 `reports/impl.md`（做了什么 / 测试覆盖 / 验证输出 / 未决问题）

## 收尾

向用户汇报三份报告的路径与结论摘要。若任一阶段 verdict 为 `{"ok": false}`，停下汇报原因，不要硬闯。
